# VS Code Setup

자주 쓰는 VS Code 설정을 템플릿에서 적용하는 스킬이다. 같은 템플릿을 두 가지 범위로 적용할 수 있다.

| 모드 | 적용 범위 | 설치 위치 | 상세 문서 |
| --- | --- | --- | --- |
| **전역** | 이 PC의 모든 프로젝트 | 사용자 `settings.json` + 로컬 확장 | `references/global.md` |
| **프로젝트** | 현재 프로젝트 하나 (팀과 공유 가능) | 프로젝트 `.vscode/` | 아래 "프로젝트 모드" |

## 지원 기능

| 기능 | 설명 | 상세 문서 | 템플릿 |
| --- | --- | --- | --- |
| 마크다운 | 제목·강조 요소 색상(편집 화면 + Preview, 다크/라이트별) + 마크다운 편집 설정 | `references/markdown.md` | `assets/markdown.json`, `assets/markdown-preview.css`, `assets/markdown-preview-extension/` |

사용자가 기능을 지정하지 않고 "vscode 설정해줘"처럼 요청하면 지원 기능 전체를 적용한다.
특정 기능만 요청하면("마크다운 색상만") 해당 기능만 적용한다.
기능을 적용하기 전에 해당 기능의 상세 문서와 선택한 모드의 문서를 먼저 읽는다. 병합 시 주의점과 커스터마이징 방법이 거기에 있다.

## 모드 고르기

요청에 범위가 드러나면 그대로 따른다.

| 요청 | 모드 |
| --- | --- |
| "모든 프로젝트", "전역", "사용자 설정", "어디서 열어도" | 전역 |
| "이 프로젝트만", ".vscode", "팀원과 공유", "커밋해서 같이 쓰게" | 프로젝트 |

범위가 드러나지 않으면 적용 전에 묻는다. 두 모드는 설치 위치가 달라 결과가 크게 다르기 때문이다. 물을 때는 다음 기준을 함께 알려 준다.

- 혼자 쓰고 모든 프로젝트에서 같은 모습을 원하면 **전역**을 추천한다. 한 번만 설치하면 된다.
- 팀원에게도 같은 설정을 보여 주거나, 이 프로젝트만 다르게 하려면 **프로젝트**를 고른다. 프로젝트 설정은 전역 설정보다 우선한다.

## 전역 모드

`references/global.md`의 절차를 따른다. 요약하면:

1. 편집 화면 색상과 `[markdown]` 설정을 사용자 `settings.json`에 Edit 도구로 병합한다. `markdown.styles`는 넣지 않는다.
2. Preview 색상은 `assets/markdown-preview-extension/`과 `assets/markdown-preview.css`로 로컬 확장을 조립해 `code --install-extension`으로 설치한다.
3. 사용자 설정에 동작하지 않는 `markdown.styles`가 남아 있으면 정리할지 묻는다.

사용자 설정은 모든 프로젝트에 영향을 주므로, 기존 값과 충돌하면 덮어쓰기 전에 반드시 묻는다.

## 프로젝트 모드

### 1. 프로젝트 루트 확인

현재 작업 디렉토리를 프로젝트 루트로 본다. git 저장소라면 `git rev-parse --show-toplevel`의 결과를 우선한다.
홈 디렉토리(`~`)처럼 프로젝트 루트로 보기 어려운 위치라면 적용 전에 사용자에게 확인한다. 엉뚱한 곳에 `.vscode/`가 생기는 것을 막기 위해서다.

### 2. 기존 설정 확인

`.vscode/settings.json`이 있으면 먼저 Read로 읽는다.

- 파일이 없으면 템플릿 내용을 그대로 담아 새로 만든다.
- 파일이 있으면 **덮어쓰지 않고 병합**한다. 사용자가 이미 넣어 둔 설정을 잃지 않기 위해서다.

### 3. 결과 보고

적용이 끝나면 다음을 짧게 알린다.

- 생성 또는 수정한 파일 경로
- 적용한 기능과 주요 변경점(새로 추가한 키, 병합한 키, 사용자 확인 후 바꾼 키)
- 기능별 상세 문서의 "적용 확인" 절차 요약 (바로 반영되지 않으면 창 다시 로드: `Developer: Reload Window`)
- 전역 모드가 이미 설치되어 있다면, 이 프로젝트에서는 프로젝트 설정이 우선한다는 안내

## 공통: 설정 파일 병합 규칙

두 모드 모두 `settings.json`을 같은 규칙으로 고친다.

- VS Code의 `settings.json`은 JSONC(주석과 끝 쉼표 허용)다. 일반 JSON 파서로 읽고 다시 쓰면 주석이 사라지므로, 스크립트로 변환하지 말고 Edit 도구로 필요한 부분만 고친다.
- 템플릿에 있는 키가 기존 파일에 없으면 추가한다.
- 같은 키가 이미 있고 값이 객체면 하위 키 단위로 병합한다.
- 같은 키에 사용자가 다른 값을 넣어 두었다면 덮어쓰기 전에 사용자에게 어느 쪽을 쓸지 묻는다.
- 배열(예: `textMateRules`)은 기능별 상세 문서의 병합 방법을 따른다.
