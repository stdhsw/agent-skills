# Git PR

현재 브랜치의 작업을 GitHub PR로 올리고 머지까지 마무리하는 스킬이다. 혼자 쓰는 저장소에서 빠르게 PR을 만들고, 커밋 이력에 맞는 머지 방식을 고르도록 돕는다.

메시지를 한국어로 쓰는 이유는 `git-commit`과 같은 기준으로 커밋, PR, 머지 커밋을 한 언어로 맞추기 위해서다. `type`과 `scope`는 Conventional Commits 도구(changelog, 버전 판단)가 읽으므로 영어로 둔다.

## 한눈에 보기

| 작업 | 언제 | 상세 문서 |
| --- | --- | --- |
| PR 생성 | "PR 만들어줘", "PR, push 해줘" | `references/create.md` |
| PR 수정 | "PR 제목 바꿔줘", 커밋을 더 올린 뒤 본문 갱신 | `references/create.md` 6단계 |
| 머지 | "머지해줘" | `references/merge.md` |
| gh 준비 | `gh`가 없거나 로그인되지 않았을 때 | `references/gh-setup.md` |

| 항목 | 규칙 |
| --- | --- |
| PR 제목 | `type(scope): 한국어 설명` (type, scope만 영어) |
| 머지 커밋 메시지 | 한국어 (`--subject`, `--body`로 지정) |
| base 브랜치 | 저장소 기본 브랜치 (`gh repo view`로 조회) |
| 머지 방식 | 커밋 분석으로 추천 → 사용자 선택 |
| 브랜치 | 머지 후에도 로컬·원격 브랜치를 지우지 않음 |

## 작업 흐름

1. **gh 확인**: `gh --version`과 `gh auth status`를 확인한다. 실패하면 `references/gh-setup.md`대로 안내하고, 사용자가 완료를 알리면 다시 확인한 뒤 이어 간다.
2. **작업 문서 읽기**: 요청한 작업의 상세 문서를 읽고 그 절차를 따른다.
3. **승인 확인**: 아래 "승인" 기준으로 push, PR 생성, 머지 전에 확인이 필요한지 정한다.
4. **결과 보고**: 상세 문서의 "결과 보고" 항목을 알린다.

## 승인

push, PR 생성, 머지는 원격 저장소를 바꾸는 일이라 승인을 받고 한다. 다만 요청에 승인이 이미 들어 있으면 같은 확인을 두 번 묻지 않는다.

| 요청 | 처리 |
| --- | --- |
| "PR, push 해줘", "바로 PR 올려줘"처럼 생성·push를 명시 | 초안을 보여 주고 바로 push·생성한다 |
| "PR 만들자", "PR 초안 써줘"처럼 확인 여지가 있음 | 초안을 보여 주고 A) 이대로 생성 / B) 수정 / C) 취소 중에서 고르게 한다 |
| "머지해줘" | 분석 결과와 추천 방식을 보여 주고 방식을 고르게 한다 |
| "스쿼시로 머지해줘"처럼 방식까지 명시 | 분석 결과만 짧게 알리고 그 방식으로 머지한다 |

## 하지 않는 일

- 승인 없이 push, PR 생성, 머지 (위 "승인" 기준을 따른다)
- 강제 push (`--force`, `--force-with-lease`)
- `--delete-branch`로 브랜치 삭제
- 기본 브랜치에서 PR 생성 시도
- `gh auth login` 같은 대화형 인증 명령 자동 실행
- CI 실패를 알리지 않고 머지
- 미커밋 변경을 임의로 커밋하거나 stash
