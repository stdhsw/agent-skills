# Skill Install

이 저장소의 스킬을 `~/.claude/skills/<이름>`에 **심볼릭 링크**로 연결하는 스킬이다.

복사가 아니라 링크를 쓰는 이유는, 저장소에서 스킬을 고치면 다시 설치하지 않아도 바로 반영되게 하기 위해서다. 복사하면 두 곳의 내용이 쉽게 어긋난다.

## 이 스킬의 위치

- 원본은 저장소 루트의 `skill-install/`이다. 다른 스킬과 마찬가지로 설치 대상이므로, 자기 자신도 `~/.claude/skills`에 설치할 수 있다. 설치하면 어느 프로젝트에서든 이 저장소의 스킬을 관리할 수 있다.
- 저장소의 `.claude/skills/skill-install`은 원본을 가리키는 상대 링크(`../../skill-install`)다. 아직 전역 설치를 하지 않았어도 이 저장소에서는 바로 쓸 수 있게 하기 위해서다.

## 용어와 경로

| 이름 | 값 |
| --- | --- |
| 저장소 (`REPO`) | 이 스킬 원본이 들어 있는 저장소의 루트. 이 스킬은 링크를 거쳐 실행될 수 있으므로 실제 경로로 바꾼 뒤 구한다: `git -C "$(cd -P "<이 스킬 폴더>" && pwd)" rev-parse --show-toplevel` |
| 설치 폴더 (`DEST`) | `~/.claude/skills` |
| 백업 폴더 (`BACKUP`) | `~/.claude/skills-backup` |

## 설치 대상

`REPO` 바로 아래에서 `SKILL.md`를 가진 폴더가 설치 대상이다.

```bash
find "$REPO" -mindepth 2 -maxdepth 2 -name SKILL.md -not -path '*/.*' | sort
```

- 숨김 폴더(`.claude/`, `.git/` 등)는 제외한다. `.claude/skills/` 아래는 이 저장소 전용 프로젝트 스킬 자리이고, `skill-install`은 원본을 루트에 두고 거기서 링크만 하기 때문이다.
- 폴더 이름이 곧 스킬 이름이다.

## 건드리지 않는 것

`DEST`에는 이 저장소와 관계없는 항목도 있다. 다음은 어떤 작업에서도 만들거나 옮기거나 지우지 않는다.

- 이 저장소에 같은 이름의 스킬이 없는 항목 (예: 다른 곳에서 설치한 스킬)
- `synced/` (Claude 앱이 동기화용으로 관리하는 폴더)
- `.git/`, `.gitignore`, `README.md` 등 스킬 폴더가 아닌 파일

`DEST`가 git 저장소일 수 있다. 링크를 추가하거나 기존 폴더를 백업 위치로 옮기면 그 저장소에 변경으로 표시된다. 이 스킬은 `DEST`의 git 상태를 바꾸지 않는다. 커밋, 되돌리기, `.gitignore` 수정은 하지 않고, 변경이 생겼다는 사실만 결과 보고에 적는다.

## 상태 확인

모든 작업은 상태 확인부터 한다. 설치 대상마다 `DEST/<이름>`을 보고 다음 중 하나로 분류한다.

| 상태 | 조건 | 의미 |
| --- | --- | --- |
| `미설치` | 경로가 없음 | 설치할 수 있음 |
| `설치됨` | 심볼릭 링크이고 `REPO/<이름>`을 가리킴 | 할 일 없음 |
| `다른 링크` | 심볼릭 링크이지만 다른 곳을 가리킴 | 교체하려면 확인 필요 |
| `충돌` | 실제 폴더나 파일이 있음 | 교체하려면 확인 후 백업 필요 |

`DEST` 안에서 `REPO`를 가리키지만 대상이 사라진 **끊어진 링크**도 찾는다. 저장소에서 스킬 이름을 바꾸거나 지웠을 때 남는다.

상태 확인 명령 예시:

```bash
REPO=$(git -C "$(cd -P "<이 스킬 폴더>" && pwd)" rev-parse --show-toplevel)
DEST="$HOME/.claude/skills"
for f in $(find "$REPO" -mindepth 2 -maxdepth 2 -name SKILL.md -not -path '*/.*' | sort); do
  name=$(basename "$(dirname "$f")"); p="$DEST/$name"
  if [ -L "$p" ]; then
    t=$(readlink "$p")
    [ "$t" = "$REPO/$name" ] && s="설치됨" || s="다른 링크 → $t"
  elif [ -e "$p" ]; then s="충돌 (실제 폴더)"
  else s="미설치"; fi
  echo "$name | $s"
done
# 끊어진 링크: REPO를 가리키지만 대상이 없는 링크
find "$DEST" -maxdepth 1 -type l | while read -r l; do
  t=$(readlink "$l"); case "$t" in "$REPO"/*) [ -e "$l" ] || echo "끊어진 링크: $l → $t";; esac
done
```

결과는 표로 보여 준다.

```
| 스킬 | 상태 | 검사 |
| --- | --- | --- |
| git-commit | 충돌 (실제 폴더) | 통과 |
| vscode-help | 미설치 | 통과 |
```

"상태 보여줘" 요청이면 여기서 끝낸다.

## 검사

설치하기 전에 각 스킬의 `SKILL.md`를 검사한다. 잘못된 스킬이 설치되면 Claude Code가 스킬을 인식하지 못하거나 엉뚱하게 실행하기 때문이다.

- 첫 줄이 `---`이고 frontmatter가 `---`로 닫힌다.
- `name`이 있고 폴더 이름과 같다.
- `description`이 있고 비어 있지 않다.

검사에 실패한 스킬은 설치하지 않고 이유를 알린다. 고칠지는 사용자에게 묻는다.

## 설치

사용자가 스킬을 지정하지 않으면 모든 설치 대상을, 지정하면 그 스킬만 설치한다.

1. 상태 확인과 검사를 한다.
2. 상태별로 처리한다.
   - `미설치` → 바로 링크한다.
   - `설치됨` → 건너뛴다.
   - `다른 링크`, `충돌` → 아래 "교체"를 따른다.
3. 링크는 절대 경로로 만든다. 상대 경로 링크는 위치가 바뀌면 끊어진다.

```bash
mkdir -p "$DEST"
ln -s "$REPO/<이름>" "$DEST/<이름>"
```

### 교체

`다른 링크`나 `충돌`이면 바로 교체하지 않는다. 기존 스킬은 사용자가 따로 만들어 쓰던 것일 수 있기 때문이다.

1. 무엇이 있는지 보여 준다. 실제 폴더라면 `SKILL.md`의 `description` 첫 줄과 파일 목록을 보여 준다.
2. 교체할지 사용자에게 묻는다. 여러 개면 한꺼번에 물어도 되지만 스킬마다 답을 받는다.
3. 동의하면:
   - `충돌` → 기존 폴더를 `$BACKUP/<이름>-<YYYYmmdd-HHMMSS>`로 옮긴 뒤 링크한다. 지우지 않고 옮기는 이유는 되돌릴 수 있게 하기 위해서다.
   - `다른 링크` → 링크 파일만 지우고(`rm "$DEST/<이름>"`) 새로 링크한다. 링크가 가리키던 원본은 그대로 남는다.
4. 동의하지 않으면 그 스킬은 건너뛴다.

```bash
mkdir -p "$BACKUP"
mv "$DEST/<이름>" "$BACKUP/<이름>-$(date +%Y%m%d-%H%M%S)"
ln -s "$REPO/<이름>" "$DEST/<이름>"
```

## 제거

사용자가 지정한 스킬의 링크를 지운다.

- `설치됨`(이 저장소를 가리키는 링크)일 때만 지운다. 실제 폴더나 다른 곳을 가리키는 링크는 이 스킬이 설치한 것이 아니므로 지우지 않고 알린다.
- 링크는 `rm "$DEST/<이름>"`으로 지운다. **끝에 `/`를 붙이거나 `-r`을 쓰지 않는다.** `rm -r "$DEST/<이름>/"`은 링크가 아니라 저장소의 원본 스킬 내용을 지운다.
- 이 스킬로 백업해 둔 같은 이름의 폴더가 `$BACKUP`에 있으면, 되돌려 놓을지 사용자에게 묻는다. 동의하면 백업 폴더를 `DEST/<이름>`으로 옮긴다.

## 끊어진 링크 정리

상태 확인에서 끊어진 링크가 나오면 목록을 보여 주고 지울지 묻는다. 동의하면 `rm "<링크 경로>"`로 링크만 지운다.
